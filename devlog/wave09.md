### 直し2：⚠️列が揃わなかった原因は馬名の長さではなかった

## 13. ⚠️⚠️事前シミュレーションの週番号が、ゲームの週番号と合っていない（2026-09-17に発見）

### きっかけ
ユーザーが案Bを選んだ際の指摘：「所属厩舎の依頼が多いのがおかしいのではなく、**同じレースに
同じ厩舎の馬が何頭も出るのがおかしい。これは所属厩舎にかかわらず**」。これを測る過程で、
⭐**その症状の原因である、もっと大きな欠陥**が見つかった。

### 欠陥
`domain/bootstrap.js`は`for (let week = 1; week <= BOOTSTRAP_WEEKS(=104); week++)`で
2年ぶんの事前シミュレーションを回し、走った馬の`lastRaceWeek`に**1〜104**を書き込む。
ところがゲーム本編は`player.currentWeek = 1`から始まる。
`isDueForNextRace`は`currentWeek - lastRaceWeek >= interval`なので、
⭐**事前シミュレーションで走った馬は、本編の週が`lastRaceWeek + interval`に達するまで
出走候補にならない**——中央値88なので、**本編のおよそ2年目の終わりまで出走できない。**

**実測**（`saveSeed="stack-0"`・現役7,262頭）：

| 本編の週 | 出走予定の馬 | 内訳 |
|---|---|---|
| 1週 | 1,360頭 | **新馬のみ** |
| 12週 | 2,732頭 | **新馬のみ** |
| 52週 | 2,813頭 | 新馬2,732＋未勝利81 |
| 104週 | 4,202頭 | 新馬2,732・未勝利853・1勝271・2勝257・3勝72・オープン17 |

⚠️現役馬のクラス分布自体は健全（新馬2,732／未勝利2,179／1勝1,191／2勝687／3勝296／
オープン177）。**馬は居るのに走れないだけ。**

### これが引き起こしていたこと（ユーザーの指摘の原因）
週の番組表は新馬戦を週2〜7本しか組まないのに、出走予定の新馬が800〜2,700頭いる。
`matchRaceForHorse`は各馬に合うレースを1つ選ぶので、⭐**6件の依頼がごく少数のレースに
集中する**。その結果、同じレースに同じ厩舎の馬が3頭・4頭・6頭と並ぶ。
⚠️**合意済みのモックが「1レースに5頭」という珍しい形になっていたのも、これが理由。**

### 併せて疑わしくなる過去の実測（§10・§11）
⚠️**以下はすべて「新馬戦しか行われない世界」で測った値**であり、直した後に測り直す必要がある：
- 「52週では重賞の依頼が1度も出ない」（§11）——オープン級の馬が走れないので当然そうなる。
- 「1週に埋められる鞍数の上限は平均2.84鞍」（§11）
- 「依頼の62.6%が所属厩舎・1週に出てくる厩舎は平均2.29軒」（2026-09-17の実測）
- 「重賞の依頼が初めて出るのは平均89週」（§10 段4）

### 直し方（Sonnetが実装する）
`bootstrapRoster`が返す直前に、全馬の`lastRaceWeek`から`BOOTSTRAP_WEEKS`を引く
（事前シミュレーションの最終週＝本編の第0週になる）。⚠️`nextRaceIntervalWeeks`は
そのままでよい。⚠️直した後に§10・§11の実測をやり直すこと。

### 同じレース・同じ厩舎の上限（2026-09-17にユーザーが決定）
⭐**3頭まで**。⚠️実際のレースの出走馬（`runNpcWeeklyRaces`）の側は、同じ選び方を再現して
測ったところ4頭以上は0件だった（63レース・1頭96.9%／2頭3.0%／3頭0.2%）ので、
**上限が要るのは依頼（`generateWeeklyRequests`）の側**。ただし上の欠陥を直すと依頼の

## 16. 訂正：0回の馬が弾かれる原因は収得賞金ではなく馬場適性だった（2026-09-17）

ユーザーの問い：「0回の馬が永久に弾かれると言っているけど、クラス分けが機能していないのか？」

### ⭐クラス分けは機能している
| 開始時のクラス | 頭数 | 1年で走った平均 | 1度も走らなかった馬 |
|---|---|---|---|
| 新馬 | 2,484 | 2.24回 | 95頭（3.8%） |
| 未勝利 | 2,493 | 4.79回 | 709頭（**28.4%**） |
| 1勝 | 1,151 | 6.92回 | 222頭（19.3%） |
| 2勝 | 665 | 6.40回 | 111頭（16.7%） |
| 3勝 | 291 | 7.35回 | 13頭（4.5%） |
| オープン | 184 | 8.67回 | 1頭（0.5%） |

**新馬クラスは開始時2,487頭→52週後95頭で、96.2%がデビューできている。** クラスごとに
別のプールから選ばれる仕組みは正しく働いている。⚠️§15に書いた「収得賞金順で上から取るため
下位の馬が永久に弾かれる」は**推測であり、実測すると誤りだった**。

### 本当の原因：馬場適性
| | 得意なほうの馬場適性 |
|---|---|
| 1年で0回だった馬（1,205頭） | ×**11.5%**／△**59.9%**／○18.4%／◎10.1% |
| 1回以上走った馬（6,045頭） | ×0.0%／△17.3%／○57.3%／◎25.4% |

**原因は2つ**：
1. ⚠️⚠️**芝もダートも×の馬は、どのレースにも出られない**（`canRaceOnSurface`が両方falseに
   なる）。`generateSurfaceAptitude`は得意なほうを`max(levelA, levelB)`で決めるので、
   両方が×になる確率は`P(level=×)²=0.125²`＝**1.56%**（計算値・実測の139頭と整合）。
   ⭐**生まれた時点でこの世界で1度も走れない馬が、全体の約1.6%いる。**
2. `preferSuitedRunners`が◎○の馬を先に取り、足りない分だけ△で埋める。得意な馬場が
   △止まりの馬（全体の17.3%）は枠が常に足りている状況では永久に後回しになる。

### 直すべき2点（`TODO.md` #97）
- **両方×の馬を作らない**——`generateSurfaceAptitude`で、少なくとも片方は△以上にする。
- **△の馬にも枠を回す**——`preferSuitedRunners`が◎○だけで埋め切らないようにする。

## 17. ⭐ローテーションの作り直し（2026-09-17・ユーザーの指摘で方針転換）

### ユーザーの指摘
「考え方を変えて。システム的に辻褄合わせをしようとしないで。**調教師は馬の適性にあわせて
ローテーションを組むんだよ。** 例えば、この馬は芝の短距離が得意だからスプリンターズ
ステークスを目標として、セントウルステークスを目指す、そのために放牧を何週間挟んで
レースの何週間前に帰厩するとか。」

⭐**§15・§16でやっていたのは、確率と上限をいじって需給を合わせる辻褄合わせだった。**
ローテーションは乱数で引くものではなく、**目標レースから逆算して組むもの**。

### ⚠️設計書には既にそう書いてあった
`arch/horse.md`「出走馬の決定（H・第1弾-Eで確定）」：
> **各馬が次走の目標を持ち、調教師が決める。**
> 馬ごとに「前走からの週数・クラス・適距離・芝ダート」があり、調教師が条件に合うレースを選ぶ。
> 1頭年6.3走＝**約8週に1回**。

`arch/race-program.md`§7：
> 毎週コンピュータの厩舎が「次にどのレースへ出すか」を決める。枠に対して希望が多いときは
> **収得賞金の多い順**で絞る（JRAの規則）。

**実装はこの手前で止まっていた**——`pickRotationIntervalWeeks`が2〜7週の乱数を引くだけで、
目標レースという概念が無い。設計の「年6.3走＝8週に1回」とも食い違っていた（実装は平均4.5週）。

### 作り直す形

**1. 馬は目標レースを持つ**——`horse.plan`
`{ targetRaceId, targetWeek, prepRaceId|null, prepWeek|null, returnWeek }`

**2. 調教師が目標を決める**（新関数`planNextTarget(horse, cards, week)`）
- 見る範囲：今週から**24週先**までの番組表
- 候補の条件：クラスが合う／**その馬が得意な馬場**（◎○を先に、△は候補が無いときだけ）／
  適距離帯／牝馬限定／前走から**8週以上**
- 選び方：格が高いほど優先（重賞＞オープン特別＞条件戦）×適性の一致度
- 例：芝1200mが◎の馬 → 24週先までの芝短距離の重賞を探す → スプリンターズS（第38週）を目標に置く

**3. 逆算して予定を組む**
| 週 | 状態 |
|---|---|
| 前走の翌週〜帰厩まで | **放牧**（出走候補から外れる） |
| 前哨戦の3週前 | **帰厩** |
| 本番の6週前 | **前哨戦**（条件の合うレースがあれば） |
| 本番の週 | **目標レース** |

**4. 出走登録と除外**（JRAの規則・既存の設計のまま）
- 各レースに、そのレースを目標にした馬が登録される
- 枠（`drawFieldSize`）を超えたら**収得賞金の多い順**で絞る
- ⭐**除外された馬は、その週のうちに目標を組み直す**——これで滞留が消える
  （今は`lastRaceWeek`が更新されず永久に出走予定のまま積み上がっていた）

**5. 依頼はこの結果から作る**——今週出走予定で騎手が決まっていない馬から12件

### ⚠️現役馬の数が1976年のレース数に対して多すぎる

| | 値 |
|---|---|
| 年間のレース数 | 2,860本（実測の平均55本/週×52） |
| 年間の延べ出走 | 31,517頭（×平均11.02頭） |
| 1頭が年6.3走するなら釣り合う現役馬 | **5,003頭** |
| 今の設定 | **7,600頭**（⚠️実際に生きているのは7,279頭。31,517÷7,279＝年4.33走） |

⚠️**「走りたい馬が収容力の6〜7倍」（§15）は、ローテーションが壊れた状態の症状の値**——
全頭が永久に出走予定のまま積み上がった結果である。⭐**設計どおり年6.3走で回った場合の
