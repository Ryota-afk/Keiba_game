## 1. 着手前の決め直し5件（2026-09-16にユーザーが決定）

`TODO.md` #24が「着手前に決め直すこと」として挙げていた5件。⚠️どれも2026-09-04の
監査で「正本と今日の決定が食い違っている」と分かったまま第4弾へ送られていたもの。

| 問い | 決定 | 正本の置き場 |
|---|---|---|
| ①ランクの循環（中堅になるには重賞勝ち・重賞に乗るには中堅） | **重賞に乗れるかの判定にランクを使わない。調教師と馬主への信頼で決める** | `src/data/ranks.js`のコメント |
| ②重賞の判定に馬主の信頼を入れるか | **入れる** | `ARCHITECTURE.md`§6 |
| ③週末に1場か1日1場か | **1日1場**（土曜と日曜で別々の競馬場へ行ける） | `ARCHITECTURE.md`§2 |
| ④断るコスト | **主戦を張っている馬の依頼を断ったときだけ、その厩舎の信頼が下がる** | `ARCHITECTURE.md`§2 |
| ⑤得意分野が出走頻度に効くか | **効かない。馬の強さに効く** | `arch/horse.md` |

### ①の理由
中堅へ上がる条件が`gradedWin`（重賞を勝つ）なのに、判定表は「G3・G2に乗るには中堅が要る」
としていた。⭐**実際の競馬でも、調教師と馬主が信用すれば若手に重賞の鞍が回る。**
ランクは平日の枠・スキル枠・適性の上限（Sにできる数）だけを決める役に絞る。

### ③の理由と、それが弱める締め付け
⚠️**2026-09-04の正本「週末に乗れる競馬場は1つ」からの変更。** モック
（`design/mocks/riding-offers-v2.html`案C）の土日タブがそのまま使える形になる。
⚠️⚠️**そのぶん「主戦の馬が2頭、別々の競馬場で走る週が必ず来る。片方は諦めるしかない」
という締め付けが弱まる**——2頭が土日に分かれていれば両方乗れてしまう。
⭐残るのは**同じ日に主戦が2頭重なった週**だけ。⚠️それが何週に1回起きるかは未計測。
⭐その代わり④（主戦の馬を断ったら信頼が下がる）を入れたので、痛みは
「どの馬の主戦を続けるか」という判断に集まる。

### ④の理由
週6件のうち乗れるのは3件で、**毎週3件は必ず断る**。全件で信頼を下げると一方的に減り続ける。
主戦の馬に限れば、断る回数はプレイヤーが選んだ主戦の数で決まる＝**自分の判断の結果**になる。

### ⑤は今日の実装で解けた
2026-09-04に「得意分野は出走頻度に効く」と「馬の強さに効く」の2つの決定が同じ日に出て
食い違っていた。⭐**どの馬場のレースに使うかは、2026-09-16に入れた`preferSuitedRunners`
（その馬場を得意とする馬から先に出走させる）が馬自身の芝ダ適性で決めるようになった**
（`devlog/wave08.md`§8-4）。ここに調教師の得意分野をもう一度掛けると二重に数えることになる。

## 3. 着手前の実測（2026-09-16）——依頼の中身

`generateWeeklyRequests`が実際に返す物を、1976年で始めた52週ぶん測った（1シード）。

| 測ったもの | 実測 | 根拠 |
|---|---|---|
| 1週あたりの依頼の件数 | 6.0件 | 実測 |
| 乗れる件数 | 3件 | `weeklyRequests.js`の`RIDABLE_SLOTS_PER_WEEK`（設定値） |
| 別の依頼と同じレースに入っている件数 | 129件／312件＝41% | 実測 |
| **依頼が入っている別々のレースの数** | **平均3.52** | 実測 |
| 1週に依頼が来る競馬場の数 | 平均2.15か所 | 実測 |
| 天気予報が外れる割合 | 22.4% | 実測 |

⚠️⚠️**訂正（同日）**：最初この節に「実質の選択肢は『6件から3件』ではなく『京都の1鞍か
中山の1鞍か』の2つしかない」と書いたが、**誤りだった**。報告文の検査で指摘され、測り直した。
6件が同じレースに重なっていても、**別々のレースが3つ以上ある週は44週＝85%**あり、
そこでは3件とも乗れる。正しくは下の表。

| 依頼が入っている別々のレースの数 | 週数（全52週） |
|---|---|
| 1つだけ | 1週 |
| 2つ | 7週 |
| 3つ | 17週 |
| 4つ以上 | 27週 |

⭐**3件とも乗れる週は44週＝85%。** 残り15%（8週）は、依頼が6件来ても2件以下しか乗れない。
⚠️第1週の実例（6件のうち5件が京都・芝1800mの新馬戦）は、その少ないほうの週だった。

### ⚠️1日1場の決定との衝突（実測）

| 測ったもの | 実測 |
|---|---|
| 依頼が来る競馬場が**3か所以上**の週 | 14週／52週＝**27%** |
| 開催している競馬場のうち、依頼が1件も無い場所 | 延べ144か所のうち32か所＝22% |
| そういう場所がある週 | 29週／52週＝56% |

⚠️⚠️**1日1場なら1週に行けるのは最大2か所**（土曜1場・日曜1場）。ところが依頼が
**3か所以上に散る週が27%**ある。⭐**その週は、行こうと思っても物理的に行けない競馬場の
依頼が混ざる。** 週の画面はそれが分かる形にしないと、選べない鞍を選ぼうとすることになる。

⚠️**開催している競馬場の22%には依頼が1件も無い**（56%の週で起きる）。競馬場タブを
「開催している場所ぜんぶ」で作ると空のタブが出る。⭐**空のときの見せ方を必ず定義する。**

## 4. 実装に足りていないもの（実測で判明）

1. ⚠️⚠️**レースが土曜か日曜かというデータが無い。** `domain/weeklyCard.js`は
   `openCourses.length * 2 * racesPerDay(year)`で本数を数えているが（×2が土日）、
   **どのレースがどちらの日かを記録していない。** ⭐§1③（1日1場）はこれが無いと成立しない。
2. ⚠️**開催の回次・日次（「3回中山6日目」）のデータが無い。**
   `data/jraMeetingSchedule.js`が持つのは「その週にどの競馬場が開いているか」だけ。
   モック（`riding-offers-v2.html`）のヘッダはこれを出しているが、実データでは埋まらない。
3. ⚠️**馬主ごとの信頼値をプレイヤーが持っていない。** `player.ownerTrust`は空のまま。
   §1②（重賞の判定に馬主の信頼を入れる）はこれが無いと成立しない。
4. ⚠️**馬の年齢が依頼から取れない。** `horse.bornYear`と`player.currentYear`から計算する。


## 5. 画面の候補3案（2026-09-16・Fableサブエージェントが作成）

`design/mocks/week-offers-v3.html`（3案を縦に並べた1ファイル）と、各案のiPhone 13幅の
スクリーンショット`week-offers-v3-1.png`〜`-3.png`。方向は合意済みの案C（土日タブ＋
競馬場タブ＋レースを縦に大きく）で、それを実データで成立する完成形にした3案。

各案とも5〜6枚の状態を描いてある：①月曜に開いたところ ②その日・その競馬場に依頼なし
③週に依頼が1件も無い ④乗る馬を決めた後（同じレースの残りが薄くなる）
⑤同じ日に2か所から依頼が来て片方を決めた後 ⑥主戦の馬の行。

| 案 | 主役 | 競馬場タブの作り |
|---|---|---|
| 1 | **馬名**（一番大きい）。性別・走り方・戦績・調教師は1行の補足 | 開いている場所を全部出し、依頼の無い場所は薄い枠だけ |
| 2 | **レース条件**（1レース＝1つの表）。馬を表で並べて比べる | 依頼のある場所だけ出す |
| 3 | **3つの枠**（「あと3件」を数字でなく枠で見せる）。日と競馬場を1本の帯に畳む | 「土曜 京都 5／土曜 中山／日曜 中山 1／日曜 京都」の1段 |

⭐**「行けない競馬場」の扱い**（§3の27%の週）：片方の馬を決めた時点で、同じ日の他の
競馬場のタブを数字を残したまま薄くし、押すと「土曜は京都へ行きます。中山の依頼には
乗れません。」の1行と、乗れなくなった馬の行（薄い）を見せる。⭐諦めた馬が見える形にした
（CLAUDE.md §0-2「奪う側を隠さない」）。
却下された代案：(a)先に「土曜はどこへ行くか」を選ばせる手順を足す (b)月曜から注意書きを出す
——どちらも操作か説明文が増えるため。
