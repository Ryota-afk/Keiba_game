## §27 レースsimの設計図（2026-09-06・本筋1・`claude-opus-5`）

⚠️正本は`arch/race-sim.md`。ここには**この弾で新しく決めた計算式と、その根拠**を書く。
既に確定していたもの（実力＝素の能力×適性の噛み合い／道中は消耗の差として溜まり直線で開く／
レース傾向4種×強度3／演出の乱数と着順の乱数を分ける／カードは残り1200mと直線入り）は再掲しない。

### 何が問題だったか（ユーザーの指摘2件の原因）

| 指摘 | 原因 |
|---|---|
| 「各馬の動きが所定の位置に移動してピタッと固定される」 | `view/dreamDerbyRace.js`の`gapMetersAt`が、6つの固定時刻の乱数値を直線で結んだだけ。80秒以降は直線カードを選ぶまで**横ばい**（コードのコメントに「選択待ちの間は横ばい」と明記）。 |
| 「実況と実際のレースの状況がマッチしていない」 | `pickCommentaryLine(slot, vars, sayCount)`が、その時点の隊列を見ずにプールから無作為に引く。行に条件が無い。 |

⭐**どちらも「レースの状態」という物が存在しないことが原因。** 今あるのは
「全馬共通の基準ペース（`distanceAtTime`）＋見た目の揺らぎ（`gapMetersAt`）」だけで、
各馬の速度・位置・消耗を持つ物が無い。

### 出力の契約（表示層が使うもの）

```
runRaceSim(input) => {
  dt: 0.25,                    // 秒。サンプル間隔
  distance: Float32Array,      // [馬index * steps + step] = その時刻の通過距離(m)
  finishTime: number[],        // 馬indexごとのゴール時刻(秒)
  order: number[],             // 着順（馬index）
  events: [{ t, type, num, ... }],  // 実況が条件に使う（#21）
}
```
⭐engineは`positionAt(num, t)`（線形補間）だけを見る。**`distanceAtTime`と`gapMetersAt`は消す。**
⚠️`GAP_T`・`PRE_CONFIRM_T`と、それが参照する`T_TUT_*`もここで役目を終える。

### 4段のモデル（dt=0.25秒・2400mで576ステップ×18頭＝10,368個の数値）

各馬は**脚（energy）1.0**を持って発走する。

1. **発走（0〜2.5秒）**：`dash = 0.5×speed + 0.3×power + 0.2×mentalStrength + 乱数`。
   出遅れはここだけで起き、プレイヤーの判断にしない（`arch/race-sim.md`の既定）。
2. **位置取り（〜600m）**：宣言脚質で目標の順位帯を決める（逃げ1〜2／先行2〜5／
   中団5〜後ろから5頭目／後方それ以外＝判断カードの位置区分と同じ区切り）。
   目標へ寄る速さはspeedの差で頭打ちにする。
3. **道中（〜残り600m）**：レース傾向がペースを決め、ペースが全馬の消耗を決める。
   ⭐**同じ速度で走っていても、1秒あたりに減る脚が馬ごとに違う**——これが
   `arch/race-sim.md`の「道中は消耗の差として溜まり、直線で開く」の実装。
   `1秒あたりの消耗 = ペース係数 × 位置係数（前ほど大きい） × 斤量係数
     ÷ (0.4 + 0.6 × スタミナ正規化 × 距離適性 × 傾向への適応)`
4. **直線（残り600m〜）**：`出せる速度 = 基準 + 0.6×瞬発力 + 1.4×残りの脚`。
   脚が尽きた馬は基準を下回る（垂れる）。⭐**差し返しは起きないが、前が垂れれば差し切る。**

**判断カードの効き方**：道中の`forward`＝目標順位を前へ（消耗+）／`hold`＝維持（消耗−）。
直線の`early`＝加速の開始を早める（前を捕らえやすいが終いに垂れる）／`hold`＝遅く仕掛ける
（届かないことがある）。⚠️**覆せる量は距離適性1段ぶんを超えないこと**（`arch/race-sim.md`）。

### 選択の反映＝フォーク（前作の`resumeSim`と同じ形）

カードは走っている最中に選ばれるので、**発走時に既定の作戦で1本走らせておき、
選ばれた瞬間にその時刻から先を計算し直す**（`resumeRaceSim(result, tFork, newPlan)`）。
⭐これで「直線カードを選ぶまで隊列が横ばい」が消え、選択が着順に直接効く。

### ファイル（`CLAUDE.md`§5の依存の向き：data → core/sim → domain/view）

`src/sim/raceSim.js`（本体・純関数）／`src/sim/pace.js`（レース傾向の決定）／
`src/sim/stamina.js`（消耗式）。⚠️`sim/`はDOMもJSXも持たない＝Node単体で計測できる。

### 実装中に見つけて直した3件（いずれも数値で確認）

1. ⚠️**発走の加速度上限が1.2 m/s²しかなく、全馬が基準ペースより110m遅れたまま最後まで戻らなかった**
   （勝ちタイムが4秒遅い）。発走の2.5秒だけ8 m/s²に分けた。
   実測：先頭馬と参照ペースの差が110m→0.0mになり、生の勝ちタイムが149.8秒→142.8秒。
2. ⚠️**レース傾向ごとに勝ちタイムが6秒ずれていた**（瞬発戦は道中が遅いぶん遅くなる）。
   各プロファイルをレース全体の平均が1.0になるよう正規化した。実測：生のタイムの幅が
   144.6〜154.6秒→146.3〜150.0秒。
3. ⚠️**相手17頭の能力が0〜100に一様に散り、掲示板の3着が「大差」になる回が26%あった。**
   史実のダービー馬なので底上げした（記号+1段・速度52以上・スタミナ40以上）。実測：17%へ。
4. ⚠️**スタミナの低い馬が道中の半ばで脚を使い切り、最後方が110m以上ちぎれた。**
   消耗式のスタミナに下駄（`0.3 + 0.7×素の値`）を履かせ、距離適性の下限を0.55→0.70にした。
   実測：最後方との差の中央値が119m→60m。
5. ⚠️⚠️**上の4番の対処で新しいバグを作り、Playwrightの通しで見つけた**——道中の速度の上限を
   `vField`の1.02倍に下げてしまい、**位置取りのクランプ（1.13倍）より厳しくなった**結果、
   ⭐**全馬が上限に張り付いて同じ速度で走り、隊列が1頭も動かなくなった**
   （実測：逃げ馬7頭の距離が50秒間、小数点以下まで一致）。上限を1.13倍に戻し、
   脚が0.3を切ったときだけ下がる形（`0.94 + 0.19×脚`）にした。
   ⚠️**この弾で直そうとしていた症状そのものを、対処のしかたで再発させていた。**
6. ⚠️**発走の加速も全馬まったく同じになっていた**（同上で発見）。加速度の上限8 m/s²で
   走行速度に届くのが約2.05秒なのに、加速に要する秒数を1.0〜3.4秒と置いたため、
   大半の馬で上限側が先に効いていた。2.1〜3.6秒に直し、発走区間を2.5→3.6秒に伸ばした。
7. ⚠️**逃げ馬の目標差を0に固定していたため、逃げ馬が全頭ぴったり重なっていた**（同上）。
   目標差を3mにし、0での頭打ちをやめた（−8mまで前に出られる）。
