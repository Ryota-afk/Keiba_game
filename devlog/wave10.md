# 第10弾：ローテーションを目標レースからの逆算で作り直す

⚠️`devlog/wave09.md`が51KBに達したため、ここから分けた（CLAUDE.md §4のサイズ規律）。
経緯は`devlog/wave09.md`§15〜§17。

## 1. なぜ作り直すか（2026-09-17・ユーザーの指摘）

> 「考え方を変えて。システム的に辻褄合わせをしようとしないで。**調教師は馬の適性にあわせて
> ローテーションを組むんだよ。** 例えば、この馬は芝の短距離が得意だからスプリンターズ
> ステークスを目標として、セントウルステークスを目指す、そのために放牧を何週間挟んで
> レースの何週間前に帰厩するとか。」

⚠️**設計書（`arch/horse.md`「出走馬の決定」）には最初からそう書いてあった**——
「各馬が次走の目標を持ち、調教師が決める」「1頭年6.3走＝約8週に1回」。
**実装がその手前で止まっていた**（`pickRotationIntervalWeeks`が2〜7週の乱数を引くだけ）。

## 2. ユーザーが決めたこと（2026-09-17）

| 項目 | 決定 |
|---|---|
| 目標を探す範囲 | **52週先まで**（1年先。「来年のあのレースを目標に今年は仕上げる」を組めるようにする） |
| 前哨戦 | **必ず1つ挙げる** |
| 現役馬の数 | **厩舎数も減らす**（190厩舎×40頭＝7,600頭 → **150厩舎×35頭＝5,250頭**） |
| 1週に乗れる鞍数 | **6鞍**（依頼12件） |
| 同じレース・同じ厩舎 | **3頭まで**（`devlog/wave09.md`§13。#95を直した後に要否を測り直す） |

**釣り合いの検算**：5,250頭×年6.3走＝33,075出走／年。収容力は31,517出走／年
（2,860レース×平均11.02頭）。**5%の超過**——実際の競馬にも除外はあるので許容範囲。

## 3. 設計

### 3.1 データ（`horse.plan`）

```
plan: {
  targetRaceId, targetWeek,   // 目標のレース
  prepRaceId,   prepWeek,     // 前哨戦（必ず1つ）
  returnWeek,                 // 帰厩する週
}
```
- `plan === null` なら未計画（次の週に立てる）。
- **放牧中**＝`week < plan.returnWeek`。出走候補から外れる。
- ⚠️`lastRaceWeek`・`nextRaceIntervalWeeks`は**廃止**する（計画が置き換える）。
  `isDueForNextRace`も廃止。

### 3.2 年間の番組表を1回だけ組む（`buildYearCard`）

⚠️**性能の要**。`buildWeeklyCard`は`(saveSeed, week, year)`から決まるので、52週ぶんを
1回組んで使い回せる（約2,860本）。

⚠️**毎回2,860本を走査してはいけない**——計画を立てるのは1週あたり約640回（＝その週に
走った馬＋除外された馬）なので、素朴に走査すると1週180万回の照合になる
（`arch/race-program.md`§7の予算は1週1ms）。⭐**条件で索引を作る**：
`index[classId][surface][距離帯] = レースの配列（週の昇順）`。

### 3.3 調教師が目標を決める（`planNextTarget(horse, yearIndex, week)`）

1. **出られるクラス**を`isEligibleForRaceClass`で絞る。
2. **馬場**：その馬の`surfaceAptitude`が◎か○の面を優先。両方△なら△の面。
   ⚠️×の面は除く（#97で「両方×の馬は作らない」ようにするので、必ず1面は残る）。
3. **距離帯**：`distanceAptitude`の高い順。
4. **候補**＝索引から引いた、`week + 最短間隔(3週)` 以降・`week + 52週` 以内のレース。
5. **点数**＝格（重賞＞オープン特別＞条件戦）×適性の一致度。⚠️遠い週ほど少し減点する
   （近い目標から順に埋まるようにするため）。⚠️係数は未定——置いてから測る。
6. 一番点数の高いレースを**目標**にする。

### 3.4 逆算して予定を組む

| 週 | 状態 | 決め方 |
|---|---|---|
| 目標の週 | 目標のレース | 3.3で決まる |
| 目標の6週前 | **前哨戦** | 同じ馬場・近い距離・目標より格が下のレースを1つ（必ず挙げる） |
| 前哨戦の3週前 | **帰厩** | |
| 前走の翌週〜帰厩の前週 | **放牧** | 残り全部 |

⚠️**6週前・3週前はまだ根拠のない仮の値**。置いてから、1頭あたりの年間出走回数が
設計書の6.3走に近づくかを測って合わせる。

### 3.5 出走登録と除外（`runNpcWeeklyRaces`の書き換え）

- 今週のレースごとに、**そのレースを目標または前哨戦にしている馬**を集める。
- 枠（`drawFieldSize`）を超えたら**収得賞金の多い順**で絞る（JRAの規則・既存のまま）。
- ⭐**除外された馬は、その週のうちに`planNextTarget`を呼び直す。**
  ⚠️これが無いと、`devlog/wave09.md`§15の「永久に出走予定のまま積み上がる」が再発する。

### 3.6 依頼（`generateWeeklyRequests`の書き換え）

今週出走予定（`plan.targetWeek === week` または `plan.prepWeek === week`）で、まだ騎手が
決まっていない馬から**12件**。⚠️所属厩舎の上限（`devlog/wave09.md`§14の#94）は、
この形にしてから測り直して決める。

### 3.7 定数の変更（`domain/career.js`）

| 定数 | 今 | 変更後 |
|---|---|---|
| `STABLE_COUNT` | 190 | **150** |
| `HORSE_COUNT` | 7,600 | **5,250**（＝150×35） |
| `NPC_JOCKEY_COUNT` | 160 | ⚠️未定（厩舎数に合わせて減らすか要検討） |

⚠️`arch/race-program.md`§7の「1974年は5,800頭＝145厩舎×40」という記述とも近づく。
