# 第10弾：ローテーションを目標レースからの逆算で作り直す

⚠️`devlog/wave09.md`が51KBに達したため、ここから分けた（CLAUDE.md §4のサイズ規律）。
経緯は`devlog/wave09.md`§15〜§17。

## 1. なぜ作り直すか（2026-09-17・ユーザーの指摘）

> 「考え方を変えて。システム的に辻褄合わせをしようとしないで。**調教師は馬の適性にあわせて
> ローテーションを組むんだよ。** 例えば、この馬は芝の短距離が得意だからスプリンターズ
> ステークスを目標として、セントウルステークスを目指す、そのために放牧を何週間挟んで
> レースの何週間前に帰厩するとか。」

⚠️**設計書（`arch/horse.md`「出走馬の決定」）には最初からそう書いてあった**——
「各馬が次走の目標を持ち、調教師が決める」「1頭年6.3走＝約8週に1回」。
**実装がその手前で止まっていた**（`pickRotationIntervalWeeks`が2〜7週の乱数を引くだけ）。

## 2. ユーザーが決めたこと（2026-09-17）

| 項目 | 決定 |
|---|---|
| 目標を探す範囲 | **52週先まで**（1年先。「来年のあのレースを目標に今年は仕上げる」を組めるようにする） |
| 前哨戦 | **必ず1つ挙げる** |
| 現役馬の数 | **厩舎数も減らす**（190厩舎×40頭＝7,600頭 → **150厩舎×35頭＝5,250頭**） |
| 1週に乗れる鞍数 | **6鞍**（依頼12件） |
| 同じレース・同じ厩舎 | **3頭まで**（`devlog/wave09.md`§13。#95を直した後に要否を測り直す） |

**釣り合いの検算**：5,250頭×年6.3走＝33,075出走／年。収容力は31,517出走／年
（2,860レース×平均11.02頭）。**5%の超過**——実際の競馬にも除外はあるので許容範囲。

## 3. 設計

### 3.1 データ（`horse.plan`）

```
plan: {
  targetRaceId, targetWeek,   // 目標のレース
  prepRaceId,   prepWeek,     // 前哨戦（必ず1つ）
  returnWeek,                 // 帰厩する週
}
```
- `plan === null` なら未計画（次の週に立てる）。
- **放牧中**＝`week < plan.returnWeek`。出走候補から外れる。
- ⚠️`lastRaceWeek`・`nextRaceIntervalWeeks`は**廃止**する（計画が置き換える）。
  `isDueForNextRace`も廃止。

### 3.2 年間の番組表を1回だけ組む（`buildYearCard`）

⚠️**性能の要**。`buildWeeklyCard`は`(saveSeed, week, year)`から決まるので、52週ぶんを
1回組んで使い回せる（約2,860本）。

⚠️**毎回2,860本を走査してはいけない**——計画を立てるのは1週あたり約640回（＝その週に
走った馬＋除外された馬）なので、素朴に走査すると1週180万回の照合になる
（`arch/race-program.md`§7の予算は1週1ms）。⭐**条件で索引を作る**：
`index[classId][surface][距離帯] = レースの配列（週の昇順）`。

### 3.3 調教師が目標を決める（`planNextTarget(horse, yearIndex, week)`）

1. **出られるクラス**を`isEligibleForRaceClass`で絞る。
2. **馬場**：その馬の`surfaceAptitude`が◎か○の面を優先。両方△なら△の面。
   ⚠️×の面は除く（#97で「両方×の馬は作らない」ようにするので、必ず1面は残る）。
3. **距離帯**：`distanceAptitude`の高い順。
4. **候補**＝索引から引いた、`week + 最短間隔(3週)` 以降・`week + 52週` 以内のレース。
5. **点数**＝格（重賞＞オープン特別＞条件戦）×適性の一致度。⚠️遠い週ほど少し減点する
   （近い目標から順に埋まるようにするため）。⚠️係数は未定——置いてから測る。
6. 一番点数の高いレースを**目標**にする。

### 3.4 逆算して予定を組む

| 週 | 状態 | 決め方 |
|---|---|---|
| 目標の週 | 目標のレース | 3.3で決まる |
| 目標の6週前 | **前哨戦** | 同じ馬場・近い距離・目標より格が下のレースを1つ（必ず挙げる） |
| 前哨戦の3週前 | **帰厩** | |
| 前走の翌週〜帰厩の前週 | **放牧** | 残り全部 |

⚠️**6週前・3週前はまだ根拠のない仮の値**。置いてから、1頭あたりの年間出走回数が
設計書の6.3走に近づくかを測って合わせる。

### 3.5 出走登録と除外（`runNpcWeeklyRaces`の書き換え）

- 今週のレースごとに、**そのレースを目標または前哨戦にしている馬**を集める。
- 枠（`drawFieldSize`）を超えたら**収得賞金の多い順**で絞る（JRAの規則・既存のまま）。
- ⭐**除外された馬は、その週のうちに`planNextTarget`を呼び直す。**
  ⚠️これが無いと、`devlog/wave09.md`§15の「永久に出走予定のまま積み上がる」が再発する。

### 3.6 依頼（`generateWeeklyRequests`の書き換え）

今週出走予定（`plan.targetWeek === week` または `plan.prepWeek === week`）で、まだ騎手が
決まっていない馬から**12件**。⚠️所属厩舎の上限（`devlog/wave09.md`§14の#94）は、
この形にしてから測り直して決める。

### ⚠️⚠️深刻な問題：性能が大幅に悪化した
| | 直す前 | 直した後 |
|---|---|---|

⭐**原因を特定した**：`domain/rotation.js`の目標選び（`scoreAsTarget`・`scoreAsPrep`）が

1回だけ求め、それを使って距離ごとに繰り返し計算できる」形に分けるのが素直な直し方だが、
これは`src/sim/`への変更（新しい関数が増える）にあたるため、Sonnetの持ち場の外——
ユーザーへの確認が必要。

## §6 性能問題（#98）の修正と実測（2026-09-17・`claude-opus-5`）

### 直したこと
`sim/stamina.js`に`aptitudeParamsOf(horse)`（最適距離と適性の幅を1回だけ取り出す）と
`distanceAptitudeFrom(params, 距離)`を足し、`distanceAptitude`はその2つを呼ぶだけにした。
`domain/rotation.js`の`planNextTarget`は1頭につき1回`aptitudeParamsOf`を呼び、その値を
`scoreAsTarget`・`scoreAsPrep`へ渡す。⚠️**式は共有していて、計算結果は1つも変わらない。**

### 変わっていないことの確認（実測）
10週まわしたあとの全馬（5,094頭）の計画・戦績・クラスを並べてハッシュを取り、
直す前と直した後で一致することを確認した（どちらも`695a7ce69c0198491b42a50e8b355785`）。
⭐この確認は`git stash`で直す前のコードに戻して同じスクリプトを走らせる形で行った。

### 実測（`bench-rotation.mjs`・20週・シード`bench-rotation-0`・各1回）
⚠️**各1回の計測**。同じコードでも走らせるたびに1%ほどぶれる（下の「効かなかったこと」の
6,403msと、この表の6,362msは同じコードの別の回）。⭐**倍率が3.7〜5.9倍あるので
ぶれでは説明できないが、数%の差を論じるには足りない精度である。**
| | 直す前 | 直した後 | 倍率 |
|---|---|---|---|
| 事前シミュレーション104週 | 23,814ms | **6,362ms** | 3.7倍速い |
| 20週の`replanStaleHorses`合計 | 7,622ms | **1,298ms** | 5.9倍速い |
| 1頭あたりの計画立て | 0.207ms | **0.035ms** | 5.9倍速い |
| `advanceWeek` 1週平均 | 430ms | **104ms** | 4.1倍速い |
| 20週の`buildYearIndex`合計 | 38ms | 44ms | 変わらず（元から軽い） |

### ⚠️やってみて効かなかったこと（記録・CLAUDE.md §10）
**`collectCandidates`が作る配列（1頭あたり170〜1,170件）を無くし、候補を1件ずつ
コールバックへ渡す形**に書き換えてみたが、**速くならなかった**：事前シミュレーション
6,403ms→6,459ms・1週あたり98ms→108ms（どちらも誤差の範囲か、わずかに遅い。
⚠️**各1回の計測なので「わずかに遅い」と言い切れる差ではない。言えるのは「速くなっていない」まで**）。
配列を作る費用と、コールバック呼び出しの費用がほぼ釣り合っている。⭐**複雑になるだけなので
元の配列を作る形に戻した。** 同じ思いつきで2度手間をかけないための記録。

**計画の結果を馬の特徴で共有する（メモ化）案も測ってから捨てた**：計画を決める5つの値
（クラス・芝ダートの記号・性別・最適距離・適性の幅）の組み合わせを数えたところ、
現役5,097頭に対して**4,313通り**（1通りあたり平均1.2頭）。⚠️**省ける計算は5,097−4,313＝784回で、
全体の15.4%しかない**（⚠️最初この値を「18%」と書いたのは誤り——784÷4,313＝18.2%と、
割る数を間違えていた。省ける割合の分母は全体の5,097である。2026-09-17に報告文の検査で発見）。

### 残っている費用（構造的なもの・ユーザー決定に関わる）
1週あたり104msのうち、計画の立て直しが約65ms。内訳は**毎週1,840頭**（現役の36%）が
計画を立て直し、1頭あたり**約700件**の候補レースを見ている（1,840×700＝約129万回／週）。
1回あたり約50ナノ秒で、この形のループとしてはこれ以上詰められない。さらに速くするには
次のどちらかで、**どちらもゲームの決まりごとを変えるのでユーザー決定が要る**：
- **目標を探す範囲52週**を短くする（⚠️2026-09-17のユーザー決定・§2）
- **毎週1,840頭が立て直す**のを減らす。出走枠から外れた馬が毎週立て直しているのが主因で、
  「外れたら次の目標まで待つ」等に変えると回数は減るが、#95（走りたい馬が積み上がる）の
  再発と隣り合わせ。

## §17 「3歳以上の41%が走っていない」の原因分析（2026-09-20・Opusサブエージェント）

⚠️**計画は立っている。** `planNextTarget`が`null`を返した馬は**0頭**。計画なしの654頭は
「2歳の解禁前」646頭＋「怪我で離脱中」7頭で、正常な内訳だった。**滞留は計画が立った後に起きる。**

### 実測（52週・番組表3,084本・重賞を除く）
| 項目 | 実測 |
|---|---|
| 登録0頭で不成立 | **1,438本（46.6%）** |
| 登録1〜4頭で不成立 | 211本（6.8%） |
| 成立 | 1,435本（46.5%） |
| 登録延べ | 71,683件 |
| 出走延べ | 14,455件（**溢れ率79.8%**） |
| 1レースの平均出走頭数 | 10.07頭 |
| 実効の出走数 | **2.83走/頭/年**（理論容量6.66・目標6.3） |

⭐**空のレースと溢れるレースが同時にある。容量ではなく配分の問題。**

### 主因（効いている順）
1. ⚠️⚠️**距離の需給ミスマッチ。** ⚠️**この項の書き方は2026-09-20に訂正した——
   `devlog/wave11.md`§2を読むこと。** 生成式が作るのは37.3%であって65%ではない。
   65%は「走れなかった馬だけを集めた母集団」の数字で、原因ではなく結果である。
   `sim/stamina.js`の`optimalDistance = 1100 + stamina×2000`で
   新馬2,481頭の**65%が2400m以上・36%が2800m以上**を最適距離に持つ。一方、番組表は
   芝の2400m以上が8.3%・ダートは1.3%。⭐**全5,101頭の50%が、番組表の7.8%（240本）へ集中**。
   実例：芝2600mは年35本に対し1,023頭、ダート2400mは年39本に対し812頭が目標にしていた。
   `DISTANCE_MISMATCH_WEIGHT=50`に対し`FAR_WEEK_WEIGHT=0.3`が小さすぎ、
   **少し遠くても距離が合うレースが常に勝つ**。
2. ⚠️**新馬クラスの出口が新馬戦しかない。** `isEligibleForRaceClass`がクラスの完全一致を
   要求するため、新馬の馬は新馬戦にしか出られない。新馬2,481頭に対し新馬戦は年307本
   （1頭あたり1.25回）。⚠️**未勝利戦は626本が空のまま**。1974年の3歳の未出走1,415頭は
   **全員`shinba`のまま**だった。
3. ⚠️**収得賞金順の選抜が未出走馬を永久に後ろへ置く。** `npcWeeklyRace.js`の並べ替えで
   同じ未勝利戦の中の通過率が**賞金>0で76.3%・賞金=0で6.6%（11.5倍差）**。
   3着までしか賞金が付かないので「走らないと賞金が付かない・賞金が無いと走れない」の輪になる。
4. 需要が供給の2倍（全頭が4週以内に走りたい状態。需要13走/年・供給6.66走/年）。
5〜6. 同点のレースは先頭が総取り／クラスが食い違った登録が0.87%（昇級後も古い計画のまま）。

### ⚠️⚠️併せて見つかった別のバグ：世界が毎年縮んでいく
`processYearBoundary(1975)`を呼ぶと `{retired:134, ..., newFoals:0}`。
**新しい2歳が1頭も生まれない。** `yearBoundary.js:77`の`breedingPool.sires.length > 0`が
満たされないため（種牡馬入りの条件が「重賞勝ち・5歳終わり」で、重賞勝ちのある現役は11頭だけ）。
⚠️**現役が毎年134頭ずつ純減する。** ユーザーの「世界が動いている感じがしない」に直結する。

### 直し方の案（サブエージェントの所見）
- **案A**：目標選びに混み具合を入れる（上位k本から抽選／レースに定員を持たせる）。
  ⚠️`sim/`に触れない。処理時間が増える（未実測）。
- **案B**：新馬の馬が未勝利戦にも出られるようにする＋選抜の並べ替えを「前走からの週数」に変える。
  ⚠️`sim/`に触れない。⚠️並べ替えは**人気の付け方にも使われている**ので同時に直す必要がある
  （人気の作り直しは別途着手済み）。
- **案C**：`optimalDistance`の式を番組表の距離分布に寄せる。⚠️**`sim/`の中身に触れる**ため、
  着順・消耗・史実馬の能力変換の検証をやり直すことになる（CLAUDE.md §17に触れる）。
