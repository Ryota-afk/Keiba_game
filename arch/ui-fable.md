# デザイン・UIの仕事はFableで行う（CLAUDE.md §2・§8の実体）

⚠️2026-09-15にユーザーが明示：**「デザインやUI関連はFable以外にやらせると本当に手を抜いたものが
できてしまう」**。それまでの決まりは「Fableは設計・監査・調査だけ、実装はSonnet」で、
画面の実装もSonnetに回していた。実績：モックの`390×720`固定枠をそのまま移植して成績表が画面の外へ
出た（`devlog/wave03.md`）／§8があるのに新しく書いたCSSで級数が17種類に戻った（同§6）／
通しプレイ①の絵の指摘5件（`TODO.md` #78）。⭐**「Fableでやる」を、着手前の1手順と、
Fableサブエージェントへの固定の依頼文、という2つの形にして守れる形に変えた。**

## 1. 何が「デザイン・UIの仕事」か（判定表）

| 仕事 | 誰がやるか |
|---|---|
| §8の候補づくり（テキストモック／HTMLモック／絵の案） | **Fable** |
| 画面のレイアウト・CSS・級数・余白・配色（`src/screens/*.css`・`src/index.css`・トークン） | **Fable** |
| 画面の部品のJSX（`src/screens/*.jsx`の見た目に関わる部分・`view/`の表示用の文字列づくり） | **Fable** |
| 画面に出る文言（実況・セリフ・チュートリアル・ボタン・見出し・表記の表＝`data/*Labels.js`） | **Fable** |
| 絵（ドット絵・SVG・タイトル画面・部屋・建物・馬の姿） | **Fable** |
| ロジック（`domain/`・`state/`・`data/`の数値・`controllers/`）と、その単体検証 | Sonnet（従来どおり） |
| レースsim（`src/sim/`）の実装と計測 | Opus（従来どおり） |
| 設計・原因分析・記録 | Opus（従来どおり）。Fableでもよい |

⚠️**1つの仕事に両方が混ざるとき（例：新しい画面＝ロジック＋見た目）は、見た目の部分を切り出して
Fableに出す。**「ついでにSonnetで見た目も書く」をしない。境目は「その変更で画面の見え方・
読める言葉が変わるか」。変わるならFable。

## 2. 手順（省略禁止）

0. **着手前にモデルを確かめる。** 本体がFable（`claude-fable-5-1`）でなければ、次のどちらか：
   - ユーザーに`/model claude-fable-5-1`への切り替えを促して待つ（画面1つを丸ごと作るとき）
   - §3の依頼文でFableサブエージェント（`Agent`ツール・`model: "fable"`）に出す
     （本体がSonnetでロジックを進めながら、見た目だけ並行させるとき）
   ⚠️モデルはスクリプトでは確かめられない。この手順0を飛ばさないことだけが守りである。
1. §8の手順（候補を複数→ユーザーが選ぶ→合意→実装）はそのまま。**候補も実装もFable。**
2. Fableサブエージェントから受け取ったものは、本体で§4の検査を通してからユーザーに見せる。

## 3. Fableサブエージェントへの依頼文（毎回この骨組みで書く・省略した項目は無いものとして扱われる）

```
あなたは競馬ゲーム（React + Vite・単一HTML・スマホ縦画面・カイロソフト風の斜め見下ろし）の
デザイン担当です。この会話の文脈は一切持っていないので、以下を全部読んでから作ってください。

【ゲームの中身】騎手が主人公。（この仕事に関わる範囲を3〜6行で。画面の前後の流れも書く）

【今回の仕事】（画面名・何を作るか・候補を何案か／実装か、を1〜3行で）

【画面の要素の全列挙】（「など」で省略しない。1要素につき：何を出すか／取得元＝関数名・
フィールド名・プロパティパス／空・0・未達成のときの見え方）

【実データ・実文言】（モックに入れる値は実際のゲーム内の値をそのまま。仮名・プレースホルダー禁止）

【守る決まり】（CLAUDE.md §7・§8・§9から、この仕事に関わる行を原文のまま貼る。最低限：
縦線禁止／絵文字禁止／級数はトークンだけ・生のpx禁止／accentは読むもの・actionは押すもの／
画面に出ている情報を文章で言い直さない／心情描写を書かない／敬語の範囲／「など」禁止）

【既に却下された案と理由】（1案1行。これを書かないと同じ案が戻ってくる）

【出力の形】（例：`design/mocks/xxx-v1.html`を3案、それぞれ390px幅で開いて崩れないこと／
または`src/screens/Xxx.jsx`と`Xxx.css`を直接書く。自分でスクリーンショットを撮って
絵を見てから返すこと。「JSエラー0件」だけで終えない）

【返し方】作ったファイルの一覧と、各案が何を狙って何を捨てたかを1案2行で。
```

## 4. 受け取ったものの検査（本体で行う・§8の再発防止の実体）

```
grep -c "border-left\|border-right" <css>      # 縦線（0でなければ理由を確かめる）
grep -oP "font-size:\s*[0-9.]+px" <css> | sort | uniq -c   # 生のpx（0が正）
grep -P "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]" <jsx/html>  # 絵文字（0が正）
```
Playwrightで`devices['iPhone 13']`のスクリーンショットを撮り、**絵を見る**（CLAUDE.md §14）。
文言は`node tools/check-words.mjs`を通す（画面の文言にもA項目の言葉を使わない）。

### §4の補足：この環境でスクリーンショットを撮るときの実際（2026-09-17・週の画面で確定）
- **確認用の入口ページは`src/`の中に置く**（`src/week-harness.html`＋`src/devWeekHarness.jsx`の形）。
  Viteの起点が`src/`なので、外に置くと本編の`index.html`に差し替えられ、タイトル画面が写る。
  入口ページはコミットしない（撮り終えたら消す）。
- **Playwrightは作業用フォルダに入れ、`/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`を
  `executablePath`に渡す**（`chromium-1194`本体は`--headless=old`を受け付けない）。
  外部フォントは証明書の都合で読めないので`waitUntil: "domcontentloaded"`にし、
  **撮った絵は代替フォントである**と報告に書く。
- **台本で行を押すときは行の中央ではなく馬名の部分を押す**（`row.$eval(".wk-r__name", el => el.click())`）。
  開いた行の中央は「乗る／外す」のボタンなので、中央を押すと選択が入れ替わり、狙った状態が撮れない。
